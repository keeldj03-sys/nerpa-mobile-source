# Nerpa Mobile

Android-приложение для работы с подписками, собранное из [v2rayNG](https://github.com/2dust/v2rayNG).
Движок от upstream не тронут — `VpnService`, туннель, ядро Xray/v2ray, хранение конфигураций,
сетевой стек. Это правило форка, и каждая правка мимо него записана в `FORK.md` с причиной.
Переписаны первый запуск, выбор маршрутизации и заметная часть видимого интерфейса: ссылку человеку
выдаёт оператор сервиса, доступа к панели управления подписками у него нет.

**Origin and license.** This repository is the complete corresponding source for the
`NerpaMobile_*.apk` files distributed to users. Nerpa Mobile is a derivative work of v2rayNG
by 2dust and is distributed under the GNU GPL v3 (`LICENSE`, unchanged from upstream). The fork
starts at tag `2.3.14`, commit `aa4b05503a504a3f2e43818e6ee8ebf1caaa3df0`; `upstream/master`
(2.3.15) was merged in `df75d646`. Both pins live in `libs.lock`.

Готовый APK раздаётся вне этого репозитория: релизов здесь нет, и ветка источника обязана
соответствовать тому APK, который у пользователя. Проверить соответствие — цель разделов
«Нативные артефакты» и «Сборка APK» ниже.

## Отклонения от upstream и их причины

[`FORK.md`](FORK.md) — реестр: что изменено намеренно, почему, и что обязан проверить тот, кто
мерджит upstream. Его читают до правки, а не после. Кратко:

| область | что в форке |
|---|---|
| первый запуск | экран активации: вставленная ссылка подписки или кнопка бесплатной выдачи; гейт держит его сверху, пока нет ни одной живой подписки и ни одного вручную добавленного узла |
| маршрутизация | три режима рядом со списком узлов — `minimal` / `auto` / `max_protection`, по умолчанию `auto` |
| интерфейс | своя палитра, иконка и тексты; power-user экраны upstream (per-app proxy, ручная маршрутизация, гео-файлы, бэкап, логи, редактор подписок) скрыты из меню и настроек — в исходниках они на месте, потому что источник обязан соответствовать раздаваемому APK; в настройках есть сброс значений, для которых больше нет переключателей |
| бренд | `applicationId = ru.nerpa.mobile`, `app_name` = `Nerpa Mobile`, deep link `nerpamobile://`, User-Agent `NerpaMobile/<versionName>`, артефакты `NerpaMobile_<versionName>_<abi>.apk` |
| обновление | пункт «Проверить обновление» в настройках читает строку `<versionCode> <ссылка>` с того же хоста, что и выдача, — см. «Манифест обновления» ниже |
| вырезано | самообновление с GitHub автора, экран благодарности переводчикам, промо- и issue-ссылки из `AppConfig` |

`namespace` остаётся `com.v2ray.ang`: исходники не переименованы, меняется только id
устанавливаемого приложения. `com.v2ray.ang` на устройстве — это upstream v2rayNG, к форку
отношения не имеет и удалять его не нужно.

## Нативные артефакты

Upstream не коммитит ни `.so`, ни `.aar`: его CI скачивает `libv2ray.aar` из релиза
[2dust/AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite), а `hev-socks5-tunnel`
компилирует `compile-hevtun.sh` под Android NDK (нужна `$NDK_HOME`). В этом репозитории артефакты
не собирают, а загружают уже собранными и проверенными: [`tool/fetch-native.sh`](tool/fetch-native.sh)
скачивает их, сверяет и раскладывает в `V2rayNG/app/libs/`:

```sh
tool/fetch-native.sh              # ABI по умолчанию = те, что закреплены в libs.lock
tool/fetch-native.sh arm64-v8a    # можно перечислить явно
```

Идемпотентен: повторный запуск ничего не перекачивает и не перезаписывает. Нужны `curl`, `gpg`,
`unzip`, `python`. Каждое ожидаемое значение закреплено в
[`libs.lock`](libs.lock), и скрипт отвергает всё, что ему не равно:

- `libv2ray.aar` — ядро Xray. У этого артефакта upstream-подписи нет, поэтому закреплённый
  SHA-256 здесь единственный контроль целостности.
- `libhev-socks5-tunnel.so` и `libhevsockstun.so` — tun2socks. Отдельного релизного артефакта для
  JNI-сборки туннеля upstream не публикует, поэтому сейчас они извлекаются из подписанного
  релизного APK v2rayNG: сначала проверяется GPG-подпись APK (ключ `7694 5E9F 3E9A 168F 8070 F195
  805D 661C 134D FAF6 8903 C199 463C 31E5 AE90 3AE0`), затем хеш каждой библиотеки.

Тем, кто обновляет закрепление ядра, нужно прогонять проверку гео-данных: `tool/verify-geodata.py
V2rayNG/app/libs/libv2ray.aar` проверяет, что гео-группы, которые называют пресеты маршрутизации,
действительно есть в `.dat` внутри aar. Неизвестная ядру группа — не ошибка: она не совпадает ни с
чем, и режим продолжает называться прежним словом, молча переставая делать то, что обещает.

## Сборка APK

```sh
git submodule update --init --recursive    # нужен для compile-hevtun.sh
tool/fetch-native.sh
cd V2rayNG
./gradlew :app:assemblePlaystoreDebug      # Windows: gradlew.bat
```

Требуются JDK и Android SDK; путь к SDK указывают в не коммитящемся `V2rayNG/local.properties`.
F-Droid-флейв (`:app:assembleFdroidDebug`, пакет `ru.nerpa.mobile.fdroid`) собирается из этого же
дерева, но не раздаётся. Версии инструментов берутся из `V2rayNG/gradle/libs.versions.toml`,
`V2rayNG/app/build.gradle.kts` и `.github/workflows/build.yml` — здесь они не дублируются, чтобы не
устареть. Дистрибутив Gradle обёртка проверяет по закреплённому `distributionSha256Sum`
(`V2rayNG/gradle/wrapper/gradle-wrapper.properties`).

Адрес эндпоинта бесплатной выдачи в репозитории не хранится — это не открытые данные. Приложение
запрашивает ровно тот URL, который вбит в `BuildConfig.FREE_SUBSCRIPTION_ENDPOINT`, и ожидает
ответом ссылку подписки; формат ответа разобран в `FORK.md` (раздел 8). Без адреса приложение
собирается и работает, кнопка просто не появляется, а путь «вставленная ссылка» остаётся
доступным. Чтобы собрать сборку с кнопкой:

```sh
./gradlew :app:assemblePlaystoreDebug -P NERPA_FREE_ENDPOINT=https://<your-endpoint>
```

Тот же ключ можно положить в `~/.gradle/gradle.properties`. Пустое значение выключает и кнопку на
экране активации (`ui/activation/ActivationContract.kt:12`), и пункт в настройках
(`ui/settings/SettingsActivity.kt:249`).

## Подпись релизного APK

`:app:assemblePlaystoreRelease` подписывается ключом оператора, и только если его дали: `signingConfig`
строится из четырёх переменных окружения — `NERPA_KEYSTORE`, `NERPA_KEYSTORE_PASSWORD`,
`NERPA_KEY_ALIAS`, `NERPA_KEY_PASSWORD`, — а без них релиз не собирается вовсе и падает на
`package…Release` с перечислением незаполненного. AGP умеет выдать
неподписанный APK молча, а он выглядит ровно как годный артефакт; debug-сборки и тесты этот гейт не
задевает. Наружу от подписи уходит одно значение — отпечаток сертификата в
[`libs.lock`](libs.lock) (`release_signing`); сам ключ, путь к нему, алиас записи в нём, passphrase и
DN в дереве не хранятся и в публичный источник не попадают.

```sh
tool/build-release.sh --keystore <путь к ключу> --alias <алиас> [--skip-lint] [-- <аргументы Gradle>]
```

Путь и алиас обязательны и дефолтов не имеют — это раскладка ключа оператора, а скрипт публикуется.
`--skip-lint` дописывает исключение трёх `lintVital…PlaystoreRelease` задач, печатает в stderr, что APK
не проверены lint, и кладёт рядом с ними `lint-skipped.txt`; без него прогон идёт с lint и падает, если
Google Maven недоступен (см. `FORK.md`, раздел 10).

Скрипт спрашивает passphrase в терминале — он не попадает ни в историю shell, ни в лог, — собирает
релиз с `--no-configuration-cache --no-daemon` (запись кэша сериализовала бы пароль на диск) и после
Gradle сверяет `apksigner verify --print-certs` каждого APK с закреплённым отпечатком. Расхождение или
отсутствие дайджеста — `*.apk.rejected` и ненулевой код выхода. Релизный APK не обновляет
debug-установку: удалить прежнюю — часть раздачи. Механизм, что в нём проверено и что ещё нет —
`FORK.md`, раздел 10.

## Манифест обновления

GitHub-механизм upstream вырезан (`FORK.md`, раздел 4). Вместо него в настройках сборки с адресом
выдачи есть пункт «Проверить обновление»: один запрос на тот же хост, откуда выдаётся бесплатная
подписка — `GET <origin эндпоинта>/nerpa/latest`. Ответ — одна непустая строка:

```text
<versionCode> <https-ссылка>
```

Если код не больше кода установленного приложения — тост «Обновлений нет». Если больше — диалог
«Открыть»: браузер по ссылке из манифеста, файл человек устанавливает оттуда сам; приложение не
качает и не ставит ничего, а переустановка тем же релизным ключом сохраняет узлы и настройки. Ссылка
в манифесте обязана быть https (`http` годится только для стенда на `127.0.0.1`/`localhost`); код
версии и адрес на экран не выводятся.

Выкладка новой версии — после релизной сборки: выложить APK на хост выдачи, записать строку
`<versionCode> <ссылка>` в файл, который сервер отдаёт по `/nerpa/latest`, и переснять снимок
публичного зеркала по этому же дереву. Строка имеет смысл только при коде, большем розданного:
сейчас это `6000755` (множитель карты 6; предыдущие эры — 4 и 5, их коды уже розданы), следующая
версия снова поднимает множитель на единицу.

## Набор ABI — читать до любой раздачи

**Годны четыре ABI и universal.** В [`libs.lock`](libs.lock) закреплены `arm64-v8a`, `armeabi-v7a`,
`x86` и `x86_64` релиза 2.3.14 — по две туннельные библиотеки на архитектуру, каждая со своим
SHA-256 и размером. `tool/fetch-native.sh` без аргументов выкладывает все четыре, а
`:app:assemblePlaystoreDebug` из этого дерева даёт пять APK: четыре per-ABI плюс `universal`.

Список ABI при этом не переписывается руками: ABI попадает в сборку только когда в его каталоге
`app/libs/<abi>/` лежат **обе** библиотеки (`libhev-socks5-tunnel.so` и `libhevsockstun.so`), а
`universal` — только когда выложены все четыре. Конфигурация падает с внятным текстом, если выложена
лишь одна из двух, если не выложена ни одна, или если `-P ABI_FILTERS` назвал ABI без
библиотек. Раньше без этого APK собирался, устанавливался, запускался и молча терял tun-режим ровно
там, где его включают, — ядро (`libgojni.so`) при этом на месте.

## Две роли: основной файл и запасной

«Годны пять» не значит «пять в канал». Собраны и подписаны все пять, а раздаются ровно два:
основной и запасной.

**`arm64-v8a` — основной, его получают все современные телефоны.** Единственный ABI, прогнанный на
реальном устройстве полной цепочкой — выдача кнопкой против живого эндпоинта и трафик через `tun0`
(`FORK.md`, раздел 10), и самый лёгкий из пяти: 32 533 775 байт.

**`universal` — запасной, его выдают, когда ABI устройства неизвестен или основной файл не
установился.** Внутри лежат обе библиотеки всех четырёх архитектур, поэтому один файл ставится и
64-битным, и 32-битным аппаратам — какой ABI возьмёт система, решает `primaryCpuAbi` устройства. У
запасного две цены. Размер: 71 940 800 байт, в 2,2 раза тяжелее основного. И непромеренность: на
ARM-устройстве этот файл не запускался ни разу — x86-эмулятор прогонял его целиком и взял `x86_64`,
значит проверены упаковка и старт ядра, а не ARM-ветка библиотек внутри него.

Остальные три файла в раздачу не входят. `x86` и `x86_64` — это образы эмулятора, а не устройства.
`armeabi-v7a` как отдельный файл больше не выдаётся, но риск по нему не исчезает: в `universal` лежат
ровно те же библиотеки этого ABI, и они не прогонялись нигде — на телефоне стоит arm64, а эмулятор ARM
не транслирует. То есть 32-битный пользователь получает запасной файл с той же непромеренной веткой, и
его первый запуск и есть первый замер.

Запасной вариант не является обновлением основного: при равном `versionCode` (параграф ниже)
`universal` поверх установленного `arm64-v8a` либо переустанавливается тем же релизным ключом, либо
отказывается — и тогда это удаление плюс чистая установка с потерей узла и настроек.

`versionCode` у всех пяти playstore-APK одинаковый (`5000755`): upstream-карта
`applicationVariants.all` даёт всем ABI playstore-ветки один множитель, и при первом собственном
релизе форка он поднят с `4` до `5` — код `4000755` уже роздан, а коды обязаны строго расти.
Раздавать по одному файлу на устройство это не мешает, но без подписанных ролей файлы в канале
неотличимы друг от друга — отсюда раздел «Две роли: основной файл и запасной» выше. У fdroid коды
различаются (`5075500`…`5075504`) и подъёмом не задеты.

Альтернатива пину — self-build `compile-hevtun.sh` (NDK и коммит `hev-socks5-tunnel` закреплены в
`libs.lock: hev_tunnel`); он позволяет не полагаться на чужие бинарники, но на этой машине он не
пройден (`Not run`). CI правка не затронула: workflow по-прежнему компилирует туннель сам, под все
четыре ABI.

## Тестирование на устройстве

Сетевой путь выдачи (200 / 403 / 429 / ротация ссылки / срок подписки) проверяется локальной
заглушкой эндпоинта на `127.0.0.1`, доступной с телефона через `adb reverse`; стенд в репозиторий
не входит. Протоколы прогонов и их результаты — в `docs/testing/`, планы этапов — в
`docs/superpowers/plans/`. Чтобы прогон не трогал рабочий пакет на телефоне, сборку ставят под
временный `applicationId` отдельным init-скриптом Gradle; сам скрипт в репозиторий тоже не входит.

## Правила для тех, кто правит код

[`AGENTS.md`](AGENTS.md) в корне и два scoped файла в `V2rayNG/app/src/main/java/com/v2ray/ang/`
(`service/`, `ui/`) — их читают до правки соответствующих путей. Они же задают порядок
синхронизации инструкций с `upstream/master` перед мерджем и требуют, чтобы правки файлов
инструкций не попадали в функциональные коммиты.
